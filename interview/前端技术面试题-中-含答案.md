# 前端技术面试题（中）含答案

不绑定具体业务项目。中档看能不能把异步、浏览器渲染、网络缓存、安全和 React 状态写对。题目要求写输出、补函数或指出失败场景。

二面建议抽 10 到 12 题。

## 01 Promise 链的错误

写出打印顺序。`catch` 后面的 `then` 还会不会跑？

```js
Promise.resolve()
  .then(() => { throw new Error('x') })
  .then(() => console.log('ok'))
  .catch(() => console.log('fail'))
  .then(() => console.log('after'))
```

**答案**

顺序是 `fail`、`after`。第一个成功的 promise 进入抛错的 `then`，这个 `then` 返回的是拒绝的 promise，所以中间的 `ok` 被跳过。`catch` 处理之后，链路恢复为成功，因此 `after` 会执行。

如果 `catch` 里继续 `throw`，后面的 `then` 不会执行，除非再接一个 `catch`。`try/catch` 包不住单独写在外面的 `promise.then`，除非在 `async` 函数里 `await`。

## 02 all 和 allSettled

三个请求要一起发，一个失败时另外两个的成功结果还要不要？该用哪个方法？

**答案**

需要全部成功才继续，用 `Promise.all`。任何一个拒绝，返回的 promise 就拒绝，并且拿不到其他成功结果。请求仍会继续在浏览器里跑，不是被取消。

失败也要保留每个结果，用 `Promise.allSettled`。它总是成功，数组成员是 `{ status: 'fulfilled', value }` 或 `{ status: 'rejected', reason }`。要取消真正不需要的请求，还得给每个 `fetch` 配 `AbortController`，Promise API 自己不会停网络。

## 03 async 里的顺序

写出顺序。

```js
async function run() {
  console.log('A')
  await Promise.resolve()
  console.log('B')
}
console.log('C')
run()
console.log('D')
```

**答案**

顺序是 `C A D B`。调用 `run` 时同步执行到第一个 `await`，所以 `A` 在 `D` 前面。`await` 后面的代码被排成微任务，当前同步代码 `D` 结束后才打印 `B`。

`await` 不是停住整个线程。它只暂停这个 async 函数，外面的调用栈继续走。

## 04 实现防抖

写一个 `debounce(fn, wait)`。连续触发时只执行最后一次，并提供取消方法。

**答案**

```js
function debounce(fn, wait) {
  let timer = 0
  function debounced(...args) {
    clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), wait)
  }
  debounced.cancel = () => clearTimeout(timer)
  return debounced
}
```

输入框搜索用防抖。窗口 resize 如果要固定间隔执行，用节流，而不是防抖。防抖的等待时间内一次都不会执行。组件卸载时调用 `cancel`，否则定时器里的 `setState` 会打到已卸载的更新上。

## 05 节流和尾调用

页面滚动每 100ms 最多处理一次，停止滚动后还要处理最后一次位置。普通“时间到了才执行”的节流会漏掉最后一点，怎样补？

**答案**

记录上次执行时间。间隔内的新调用只记住参数，并设定一个剩余时间的定时器。定时器触发时执行最后那次参数。

```js
function throttle(fn, wait) {
  let last = 0
  let timer = 0
  let lastArgs
  return function (...args) {
    const now = Date.now()
    const remain = wait - (now - last)
    lastArgs = args
    if (remain <= 0) {
      clearTimeout(timer)
      last = now
      fn.apply(this, lastArgs)
    } else if (!timer) {
      timer = setTimeout(() => {
        timer = 0
        last = Date.now()
        fn.apply(this, lastArgs)
      }, remain)
    }
  }
}
```

滚动监听还应使用 `{ passive: true }`，除非确实要 `preventDefault`。

## 06 实现 bind

写一个只绑定 `this` 和前置参数的 `bind`。

**答案**

```js
function bind(fn, thisArg, ...preset) {
  return function (...args) {
    return fn.apply(thisArg, [...preset, ...args])
  }
}
```

真正的 `Function.prototype.bind` 还有两点：绑定后的函数可以用 `new` 调用，这时 `this` 应指向新对象而不是 `thisArg`；并且 `length` 会减去已固定的参数个数。面试里写出 `apply` 版本后，能提到 `new` 的例外即可。箭头函数本身没有自己的 `this`，对它 `bind` 不能改变词法 `this`。

## 07 for...in 和 for...of

一个数组继承了一个可枚举属性。两种循环分别会看到什么？

```js
const list = ['a', 'b']
Array.prototype.extra = 'x'
```

**答案**

`for...in` 遍历可枚举的键，包括原型上的 `'extra'`，顺序也不保证是数字下标。`for...of` 走迭代器，数组迭代器只给出现有下标的值 `'a'` 和 `'b'`。

遍历数组用 `for...of`、`forEach` 或普通下标循环。`for...in` 适合普通对象的键，并且最好配 `hasOwnProperty`。给内置原型加可枚举属性会影响所有 `for...in`，不要这么做。

## 08 WeakMap 的用途

为什么组件和 DOM 节点的私有数据有时放 `WeakMap`，不放普通 `Map`？

**答案**

`WeakMap` 的键必须是对象，并且是弱引用。DOM 节点被移除后，如果没有别的引用，WeakMap 里的记录可以一起被回收。普通 `Map` 会一直抓住这个节点，节点的监听和子树都释放不掉。

WeakMap 不能遍历，也没有 `size`。它不适合当需要列出所有键的缓存。缓存请求结果通常用普通 `Map`，并自己设置过期或删除。

## 09 宏任务之间会不会插渲染

连续两个 `setTimeout(fn, 0)`，浏览器会不会保证中间画一帧？

**答案**

不保证。两个定时器都是宏任务，浏览器可以在它们之间寻找渲染时机，但脚本如果不断用 `setTimeout` 排队，渲染会被推迟。要跟屏幕刷新对齐，用 `requestAnimationFrame`。rAF 回调在一帧绘制之前执行，适合读写动画位置。

`setTimeout` 还有最小延迟，后台标签页会被节流到更慢。不要用它实现倒计时的精确时钟，到期时间应拿目标时间戳和 `Date.now()` 比较。

## 10 事件循环综合题

写出顺序。

```js
console.log(1)
setTimeout(() => console.log(2), 0)
Promise.resolve().then(() => {
  console.log(3)
  queueMicrotask(() => console.log(4))
})
requestAnimationFrame(() => console.log(5))
console.log(6)
```

**答案**

同步是 `1`、`6`。接着清空微任务，打印 `3`，`queueMicrotask` 又排入当前微任务队列，所以紧接着 `4`。然后浏览器才有机会渲染，rAF 的 `5` 在绘制前。`setTimeout` 的 `2` 是后续宏任务，通常在这一帧之后，所以常见顺序是 `1 6 3 4 5 2`。

如果主线程很忙，rAF 和 timeout 的相对顺序可能被推迟，但微任务一定在下一次渲染之前排空。答题时要把这个前提说出来。

## 11 层叠上下文计算

父元素 `opacity: 0.99; z-index: 1`，里面的子元素 `z-index: 100`。旁边一个兄弟 `z-index: 2`。谁在上面？

**答案**

兄弟在上面。父元素因为 `opacity` 小于 1 且具备定位和 z-index，形成独立层叠上下文。外部只拿父元素的 `z-index: 1` 去和兄弟的 `2` 比，子元素的 `100` 出不了这个上下文。

排查盖住问题时，从目标元素向上找第一个层叠上下文，再看那个上下文整体的层级。

## 12 fixed 的包含块

弹层 `position: fixed; top: 0`，却相对中间的卡片定位，而不是视口。卡片上有什么属性会导致这样？

**答案**

祖先只要有 `transform`、`perspective`、`filter` 或 `contain: paint`，就会变成 `fixed` 的包含块。`will-change: transform` 也一样。

弹层要相对视口时，把节点挂到 `document.body`，并保证 body 到弹层之间没有这些属性。只把 CSS 改成很大的 `z-index` 解决不了包含块。

## 13 sticky 失效

`position: sticky; top: 0` 的表头跟着内容滚走。写出两个最常见原因。

**答案**

第一，任何一个祖先的 `overflow` 是 `hidden`、`auto` 或 `scroll`，sticky 就相对那个滚动容器而不是页面，祖先如果本身不滚动，看起来就像失效。第二，父元素高度和 sticky 元素一样高，没有多余的滚动范围。

sticky 元素的父级必须比它更高，并且真正滚动的容器不能用 `overflow: hidden` 把粘滞裁掉。

## 14 一行文字截断

写单行省略和多行省略。多行方案有什么限制？

**答案**

```css
.one {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
.multi {
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 2;
  overflow: hidden;
}
```

多行省略依赖旧的 flexbox 语法，文字必须是纯文本的块。中间如果有行内块、浮动或可换行的链接，截断位置会不稳定。需要精确“展示两行并在末尾放按钮”时，要用测量 DOM 高度的 JS，而不是指望 line-clamp。

## 15 选择器活着的代价

给每个列表项写 `[data-id="123"]` 这样的属性选择器，一万条时滚动变慢。属性选择器本身是不是主因？

**答案**

通常不是。滚动慢更多来自 DOM 节点数量、复杂阴影、强制同步布局和监听。属性选择器比类选择器稍贵，但匹配发生在样式计算时，一万个简单属性选择器很少是首要矛盾。

先减节点、避免在滚动中读 `offsetHeight`、少用大面积 `box-shadow` 和 `filter`。样式选择器要优化时，优先减少深度嵌套和通配符，而不是把所有属性选择器改成行内样式。

## 16 图片把布局顶开

图片加载完成后，下面的文字突然下移。写出 CSS 和 HTML 上各要补什么。

**答案**

这是 CLS。图片没有预留尺寸，加载前高度为 0。

```html
<img src="/a.jpg" width="800" height="400" alt="">
```

```css
img { max-width: 100%; height: auto; }
```

`width` 和 `height` 属性让浏览器知道宽高比，CSS 再把宽度限制进容器。也可以用 `aspect-ratio: 2 / 1`。不要等 `onload` 再把高度从 0 改成真实值。

## 17 强缓存和协商缓存

`Cache-Control: max-age=31536000, immutable` 和 `no-cache` 分别怎么走网络？

**答案**

`max-age=31536000, immutable` 在一年内直接使用本地副本，刷新也不重新验证。文件名必须带内容哈希，内容一变就要换 URL。

`no-cache` 不是不缓存。它每次都要向服务器验证，验证通过返回 `304`，浏览器用本地正文。`no-store` 才是不留副本。HTML 入口适合 `no-cache`，带哈希的 JS 和 CSS 适合长 `max-age`。

## 18 从缓存到 304 的头部

浏览器怎样判断缓存文件没变？前端构建要保证什么？

**答案**

第一次响应带 `ETag` 或 `Last-Modified`。下次浏览器发送 `If-None-Match` 或 `If-Modified-Since`。服务器认为没变就返回 `304` 且没有正文。

构建要把文件内容哈希放进文件名，而不是只改 query。CDN 如果把不带哈希的 `index.html` 也缓存一年，用户会一直拿到旧 HTML，里面的旧哈希脚本可能已经 404。入口文档和静态资源的缓存策略必须分开。

## 19 预检请求

什么请求会先发 OPTIONS？怎样减少它的次数？

**答案**

方法不是 GET、HEAD、POST，或者头里有自定义字段，或者 `Content-Type` 不是 `application/x-www-form-urlencoded`、`multipart/form-data`、`text/plain`，就会预检。`Authorization` 和 `Content-Type: application/json` 都会触发。

服务端在预检响应里给 `Access-Control-Max-Age`，浏览器在这段时间里复用预检结果。不要为了躲避预检把 JSON 伪装成简单请求，认证头该留就留。开发环境看到每个接口两个请求，先分清哪个是 OPTIONS。

## 20 XSS 在 React 里从哪进来

React 默认把插值转义。写出两种仍然会执行脚本的写法。

**答案**

```jsx
<div dangerouslySetInnerHTML={{ __html: userHtml }} />
<a href={userUrl}>链接</a>
```

第一种直接解析 HTML。第二种如果 `userUrl` 是 `javascript:alert(1)`，点击就会执行。

用户内容默认放在 `{}` 文本里。必须渲染富文本时，用成熟的消毒库按标签和属性白名单处理，链接只允许 `http` 和 `https`。`target="_blank"` 要同时加 `rel="noopener noreferrer"`，避免新页面通过 `window.opener` 控制原页面。

## 21 CSRF 和 SameSite

接口用 cookie 登录。恶意网站怎样发出带 cookie 的请求？前端单独加一个自定义头能不能完全解决？

**答案**

浏览器请求目标站点时，会按 cookie 的 `SameSite` 决定是否带上。`SameSite=None` 的 cookie 在跨站请求里仍会带上，恶意页面可以用表单 POST 打到你的接口。

自定义头会触发预检，恶意页面读不到预检通过前的响应，但真正的防护是服务端校验 CSRF token 或使用 `SameSite=Lax`/`Strict`。前端把 token 放在请求头里，只是配合。`Lax` 会在跨站 POST 时不带 cookie，顶层 GET 链接仍会带。纯前端无法阻止用户浏览器发出请求。

## 22 原型污染

`merge({}, JSON.parse(payload))` 如果 payload 含 `__proto__`，会怎样？

**答案**

不安全的深合并会把 `__proto__` 当成普通键，沿原型去改 `Object.prototype`。之后所有对象都多出攻击者写的属性，条件判断可能被绕过。

合并时拒绝 `__proto__`、`constructor` 和 `prototype`。用 `Object.create(null)` 做字典，或在赋值前用 `Object.hasOwn` 判断。JSON 里的 `__proto__` 用普通 `JSON.parse` 再点属性访问不会自动污染，危险发生在递归赋值。

## 23 受控组件的光标

每次 `onChange` 都 `setValue(event.target.value.trim())`，光标为什么会跳到末尾？

**答案**

React 受控输入在渲染时会按状态重写 input 的值。`trim` 改变了字符串长度和内容，浏览器无法把原来的选择范围对应回去，于是光标被放到末尾。中文输入法组词期间改值还会打断 composition。

展示时再 trim，或只在失焦时整理。如果必须在输入中改字符，先记下 `selectionStart`，更新后按差值设回去。组词过程用 `compositionstart` 和 `compositionend` 暂停改写。

## 24 过期的 effect

快速把依赖从 `a` 改成 `b`，`a` 的请求后返回。写出清理代码。

**答案**

```jsx
useEffect(() => {
  const controller = new AbortController()
  fetch(`/user/${id}`, { signal: controller.signal })
    .then(res => res.json())
    .then(setUser)
    .catch(error => {
      if (error.name !== 'AbortError') setError(error)
    })
  return () => controller.abort()
}, [id])
```

清理函数在下一次 effect 之前和卸载时运行。只加一个布尔 `ignore` 也能挡住 `setUser`，但网络请求还会继续。需要停掉请求时用 abort。取消错误不要显示成加载失败。

## 25 useEffect 和 useLayoutEffect

测量 DOM 高度后立刻设置另一块的位置。用哪个 hook？用错了用户会看到什么？

**答案**

用 `useLayoutEffect`。它在 DOM 更新之后、浏览器绘制之前同步执行，用户看不到中间状态。

`useEffect` 在绘制之后才运行。先画出错误位置，再跳到测量后的位置，就会闪一下。`useLayoutEffect` 里做重计算会推迟这一帧，所以只放必须在绘制前完成的读写，请求数据仍然放 `useEffect`。服务端没有布局，`useLayoutEffect` 在 SSR 里会警告，纯服务端渲染的测量要放到客户端挂载之后。

## 26 useMemo 没有生效

子组件包了 `React.memo`，父组件每次都 `<Child style={{ color: 'red' }} onClick={() => save(id)} />`。为什么还是每次都渲染？

**答案**

`memo` 浅比较 props。每次渲染都新建 style 对象和 onClick 函数，引用不同，浅比较失败。

样式如果不变，提到组件外。回调用 `useCallback`，并且它的依赖确实稳定。`useMemo` 包一个每次都变的对象没有意义。先用 React DevTools 看是哪一个 prop 变了，而不是把所有子组件都包上 memo。

## 27 状态批处理

React 18 里，`setTimeout` 中两次 `setState` 会渲染几次？

```jsx
setTimeout(() => {
  setA(1)
  setB(2)
}, 0)
```

**答案**

同一次超时回调里的两次更新会被自动批成一次渲染。React 18 不再只在浏览器事件里批处理，promise、超时和原生事件里也一样。

需要立刻读到 DOM 已经更新的结果时，把第二次更新放进 `flushSync`。那会强制同步渲染，失去批处理，不要包住高频输入。

## 28 自定义 hook 的规则

为什么不能把 `useState` 写在 `if` 里面？自定义 hook 的名字有什么要求？

**答案**

React 靠调用顺序把每次的 hook 状态对上号。条件里少调用一次，后面的 hook 会读到别人的状态。循环里调用同样不行。

自定义 hook 必须叫 `use` 开头，这样 lint 才按 hook 规则检查。它每次渲染都会执行，不是只在第一次执行。把异步请求直接写在自定义 hook 的函数体里，而不是 effect 里，会造成每次渲染都请求。

## 29 上下文导致的渲染

ThemeContext 的 value 写成 `{{ theme, setTheme }}`。主题没变，为什么消费者仍然渲染？

**答案**

每次 Provider 渲染都创建一个新对象，Context 用 `Object.is` 比较 value，引用变了就通知所有消费者。

把 value 放进 `useMemo`，依赖只留 `theme` 和稳定的 `setTheme`。`setTheme` 来自 `useState`，本身是稳定的。消费者再拆成只订阅主题的组件，避免整个页面都在 Provider 下面读 context。

## 30 列表状态上移

每个子项内部都有一份选中状态，父组件的“全选”拿不到它们。状态该放哪？

**答案**

选中 id 放到父组件，用 `Set` 或数组保存，子项变成受控组件，接收 `checked` 和 `onChange`。需要全选、计数、提交时，状态必须在这些操作都能访问的那一层。

不要用 ref 去逐个调子组件的方法来收集状态，这样数据流看不出来。只在子项内部使用、父组件不关心的临时输入，才留在子组件。

## 31 类型收窄

`value` 是 `string | null`。怎样写判断，让 if 里面的类型变成 `string`？

**答案**

```ts
function lengthOf(value: string | null) {
  if (value === null) return 0
  return value.length
}
```

条件判断后，TypeScript 会从联合类型里剔除 `null`。也可以用 `typeof value === 'string'`。对象用可辨识字段：`kind: 'text' | 'image'`，`switch (data.kind)` 后每个分支里的类型是明确的。

类型断言 `value as string` 不会做这个判断，运行时仍然可能是 `null`。

## 32 unknown 和 any

`JSON.parse` 的结果声明成 `any` 和 `unknown`，后面的使用有什么差别？

**答案**

`any` 关闭检查，点任何属性和调用都可以，错误要到运行时才出现。`unknown` 表示还不知道类型，除了赋给 `unknown` 或 `any`，使用前必须判断或断言。

接口响应先标成 `unknown`，再用类型守卫检查字段，通过后才进入业务类型。守卫要真正读字段，而不是一个永远返回 `true` 的函数。

## 33 Partial 和必填更新

更新用户时所有字段都可选，但提交创建时每个字段都必填。用哪些工具类型？

**答案**

```ts
type User = { id: string; name: string; age: number }
type UpdateUser = Partial<Pick<User, 'name' | 'age'>>
```

`Partial` 把每个字段变成可选。`Pick` 先选出允许修改的字段，避免 `id` 也被改掉。`Omit<User, 'id'>` 适合创建参数。`Required` 把可选重新变回必填。

工具类型只存在于编译期，不会在运行时删掉多余字段。请求体要不要带未知字段，需要代码自己处理。

## 34 虚拟列表的窗口

一万行、每行固定 40px，滚动容器高 400px。写出应该渲染的下标范围，以及总高度怎样保留。

**答案**

`start = Math.floor(scrollTop / 40)`，可见条数是 `Math.ceil(400 / 40)`，再加上前后缓冲，比如各 5 条。只渲染 `start` 到 `end` 的数据。

容器内部放一个高度为 `10000 * 40` 的占位，内容用 `transform: translateY(start * 40)` 移到滚动位置。不能把一万个节点都挂进 DOM。滚动事件里不要每次都 `setState` 整个数据数组，只更新开始下标。

## 35 长任务和输入延迟

点击按钮后 300ms 才有反应，性能面板里有一根 280ms 的长任务。这更像网络慢还是主线程被占？

**答案**

更像主线程被占。网络慢会让数据晚到，但点击到事件回调开始之间如果已经有长任务，回调根本排不上来。长任务指占用主线程超过 50ms 的脚本、布局或绘制。

把同步大循环拆开，每处理一批用 `requestAnimationFrame` 或让出主线程。不要在点击回调里同步过滤上万条数据再渲染全部节点。INP 关注的是从交互到下一帧绘制，不只是接口时间。

## 36 图片格式和尺寸

同一张图在手机上下载了桌面用的 2000px 原图。HTML 怎样让浏览器选小图？

**答案**

```html
<img
  src="/a-800.jpg"
  srcset="/a-400.jpg 400w, /a-800.jpg 800w, /a-1600.jpg 1600w"
  sizes="(max-width: 600px) 100vw, 800px"
  width="800"
  height="600"
  alt=""
>
```

浏览器按 `sizes` 估算显示宽度，再结合屏幕像素比从 `srcset` 里选。CSS 把图片压小，不会减少已经下载的字节。首屏大图还可以 `fetchpriority="high"`，屏外图片用 `loading="lazy"`。

## 37 字体加载

自定义字体未到时，文字先隐藏，到了以后整段变宽。这是什么现象，怎样减轻？

**答案**

默认可能是 FOIT，字体超时前文字不可见。字体到达后度量不同，会造成布局偏移。

```css
@font-face {
  font-family: Brand;
  src: url('/brand.woff2') format('woff2');
  font-display: swap;
  unicode-range: U+4E00-9FFF;
}
```

`swap` 先用后备字体显示，再替换。为后备字体设置相近的 `size-adjust` 和行高，能减少跳动。只把页面用到的字符打进字体文件，不要整包下载。

## 38 源码映射

生产环境报错只有 `a.js:1:48392`。怎样看到源码位置，又不要把源码公开给所有访问者？

**答案**

构建时生成 hidden source map，或把 map 上传到错误监控平台，不要以 `.map` 形式部署到公开静态目录。上报的错误带上打包文件名、行号和版本号，平台用对应版本的 map 还原组件栈。

source map 里包含源码和路径。公开 map 等于把前端源码交给任何人。本地开发可以 inline map，生产构建要按版本保留 map，否则下次发版后旧错误无法还原。

## 39 Tree shaking 失效

库用了 `export default { a, b }`，业务只调用 `a`。为什么 `b` 仍在产物里？

**答案**

打包器只能对 ES 模块的静态 `export` 做摇树。整个对象作为默认导出时，属性是运行时挂上去的，打包器不知道 `b` 没有副作用，于是保留整个对象。

库要写成具名导出 `export function a()`。包的 `package.json` 里 `sideEffects: false` 表示模块可以安全删除，如果模块顶层改了全局样式或原型，就不能标成 false。业务侧不要把整个库 `import _ from 'lodash'`，改为具名或路径导入。

## 40 一条请求的前端超时

`fetch` 没有 timeout 参数。怎样在 5 秒后取消，并区分超时和用户主动取消？

**答案**

```js
async function fetchWithTimeout(url, ms) {
  const controller = new AbortController()
  const timer = setTimeout(() => controller.abort(), ms)
  try {
    return await fetch(url, { signal: controller.signal })
  } finally {
    clearTimeout(timer)
  }
}
```

`abort` 抛出的错误名是 `AbortError`，超时和手动取消看起来一样。要区分时，用自定义 `AbortController` 的 `reason`，或在超时分支先设一个标记。清除定时器放在 `finally`，成功后不要让定时器再去 abort 下一次复用的 controller。
