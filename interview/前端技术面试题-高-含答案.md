# 前端技术面试题（高）含答案

不绑定具体业务项目。高档看异步调度、渲染管线、缓存和安全边界、React 并发模型，以及能不能把一段实现写完整。答案包含可运行的核心代码和失败场景。

三面建议抽 8 到 10 题。

## 01 把事件循环排满

写出打印顺序，并说明渲染插在哪里。

```js
console.log('script')
setTimeout(() => console.log('timeout'), 0)
Promise.resolve().then(() => {
  console.log('micro')
  requestAnimationFrame(() => console.log('raf-from-micro'))
})
requestAnimationFrame(() => console.log('raf'))
console.log('script-end')
```

**答案**

同步打印 `script`、`script-end`。当前栈结束后先跑完微任务，打印 `micro`。这次微任务里又注册了一个 rAF。浏览器进入渲染机会时，按注册顺序执行已经登记的 rAF，所以是 `raf`，然后是 `raf-from-micro`。`timeout` 属于后续宏任务，通常在这一帧提交之后。

稳定顺序是 `script`、`script-end`、`micro`、`raf`、`raf-from-micro`、`timeout`。如果标签页在后台，rAF 可能被暂停，而 timeout 只是被延长，两者不能拿来互相替代。回答时要说明微任务一定在下一次渲染前清空，包括微任务里新加的微任务。

## 02 实现具备并发上限的调度

写 `mapPool(list, limit, worker)`。最多同时跑 `limit` 个异步任务，结果顺序和输入一致，某个任务失败则整体失败。

**答案**

```js
async function mapPool(list, limit, worker) {
  const result = new Array(list.length)
  let next = 0
  async function run() {
    while (next < list.length) {
      const index = next
      next += 1
      result[index] = await worker(list[index], index)
    }
  }
  const runners = Array.from({ length: Math.min(limit, list.length) }, run)
  await Promise.all(runners)
  return result
}
```

下标必须在 `await` 之前取走，否则多个 runner 会读到同一个 `next`。失败时 `Promise.all` 会拒绝，但已经发出的任务不会自动停止。若要停止，worker 需要接收同一个 `AbortSignal`。`limit` 小于 1 时应直接抛错。

## 03 防抖加上最大等待

搜索框停顿 300ms 才请求。用户连续输入 5 秒时，也不能 5 秒都不请求。给 `debounce` 增加 `maxWait`。

**答案**

记录第一次被推迟的时间 `start`。每次调用重新设定尾定时器。如果 `Date.now() - start >= maxWait`，立即执行并清空 `start`。尾定时器触发时也要清空 `start`。

```js
function debounce(fn, wait, maxWait) {
  let timer = 0
  let start = 0
  let args
  function invoke() {
    clearTimeout(timer)
    timer = 0
    start = 0
    fn(...args)
  }
  return function (...next) {
    args = next
    const now = Date.now()
    if (!start) start = now
    if (now - start >= maxWait) invoke()
    else {
      clearTimeout(timer)
      timer = setTimeout(invoke, wait)
    }
  }
}
```

`maxWait` 小于 `wait` 时，行为应等同于按 `maxWait` 节流。取消函数要把 `timer` 和 `start` 都清掉，否则下次调用会继承旧的起始时间。

## 04 闭包造成的 DOM 泄漏

SPA 路由切走后，节点已经不在文档里，堆快照却仍能看到它。怎样从代码上判断是闭包抓住的？

**答案**

在保留路径里找脱离文档的 DOM，看谁引用它。常见路径是全局事件总线、未清理的 `setInterval`、Promise 回调，以及模块级数组把处理函数存了下来。处理函数的闭包里有这个节点。

修复不是把变量改名，而是在路由卸载时移除监听、`clearInterval` 和取消订阅。使用 `WeakRef` 不能代替清理，它只让你观察对象是否还在。堆快照里如果保留者是 `Detached HTMLDivElement`，再向上看第一层就是泄漏点。

## 05 关键渲染路径

一个页面有大的同步脚本在 `<head>`，还有未指定尺寸的首屏图。LCP 慢时你先看哪两件事？

**答案**

先看 LCP 元素是图片还是文本块，以及它被什么挡住。头部同步脚本会推迟 HTML 解析和首次绘制，应改成 `defer` 或把关键 CSS 内联、非关键脚本后移。LCP 图片要尽早开始下载，给它 `fetchpriority="high"`，不要懒加载首屏图，并用 `srcset` 避免下太大的文件。

第二看是否有布局抖动把 LCP 时间推后。图片、字体和异步插入的横幅都会改变最大元素。LCP 记录的是最大内容绘制的时间点，脚本执行很长时，这个时间点会跟着往后。

## 06 合成层的代价

给列表每一项加 `will-change: transform` 后，低端机滚动更卡。浏览器具体多做了什么？

**答案**

`will-change: transform` 和实际的 `transform` 会把元素提升为独立合成层。每一层都要内存来存放位图。几百行列表就是几百张层，内存和合成时间上升，滚动时 GPU 和内存带宽成为瓶颈。

只在正在动画的那一项上添加，动画结束用 `transitionend` 移除。大面积 `filter`、`backdrop-filter` 也是同样的代价。滚动性能先保证层数少、不在滚动监听里读布局。

## 07 读布局和写布局分开

实现一个批量测量：先读一组元素的高度，再按高度写它们的 `translateY`，并且全程最多触发一次布局。

**答案**

```js
function stack(elements) {
  const heights = elements.map(el => el.getBoundingClientRect().height)
  let top = 0
  elements.forEach((el, index) => {
    el.style.transform = `translateY(${top}px)`
    top += heights[index]
  })
}
```

所有读在写之前完成。浏览器可以在第一次读取前把脏布局算完，后面的读取使用这次结果。如果在循环里读一个、写一个，每次写都把布局弄脏，下一次读又强制重算。写 `transform` 不改变布局，比写 `top` 更合适。这个函数如果在一帧里被调用多次，可以再合并到同一个 rAF。

## 08 不定高虚拟列表

行高未知。写出渲染窗口、测量和滚动补偿的数据结构。

**答案**

用数组 `heights` 保存每一行最近一次测到的高度，未知时用估计值 `estimated`。另算前缀和 `offsets`，`offsets[i]` 是第 i 行之前的总高度。滚动位置 `scrollTop` 用二分在 `offsets` 里找 `start`。`end` 从 `start` 累加，直到超过 `scrollTop + viewport`，再加缓冲行。

渲染后用 `ResizeObserver` 测量真实高度。如果视口上方的行变高 `delta`，执行 `scrollTop += delta`，否则用户看到的内容会跳。总高度是前缀和的最后一项，不要用行数乘估计值一直不修正。快速滚动时可以先用估计值占位，测量到达后再更新前缀和。

## 09 入口文件的缓存策略

带哈希的 `app.8f3a.js` 可以缓存一年。`index.html` 为什么不能用同样的响应头？请写出两类资源的 `Cache-Control`。

**答案**

HTML 里写着下一版脚本的文件名。HTML 如果也被缓存一年，浏览器不会来拿新的文件名，新版本永远进不去。脚本文件名变了，旧脚本可以永久缓存，因为它的 URL 不会再被新 HTML 引用。

```text
index.html: Cache-Control: no-cache
app.8f3a.js: Cache-Control: public, max-age=31536000, immutable
```

`no-cache` 每次向服务器验证 HTML。部署时要先上传新的哈希资源，再切换 HTML，否则新 HTML 会引用尚未上传的脚本。回滚也是先把 HTML 指回旧哈希，旧脚本仍然在缓存里。

## 10 HTTP/1.1 的队头阻塞

浏览器对同一域名的 HTTP/1.1 连接大约六个。页面有三十个小图标请求时会发生什么？HTTP/2 改善的是哪一层？

**答案**

超过连接数的请求在浏览器里排队，一个慢响应会占住连接，后面的响应即使已经准备好也不能复用这条连接。这是应用层的队头阻塞。

HTTP/2 在一条连接上多路复用多个流，小文件不必各占一个连接。它没有消除 TCP 层的队头阻塞，一个丢包仍可能影响同一连接上的多个流。HTTP/3 改用 QUIC，丢包只影响对应的流。前端能做的是减少请求数、合并关键资源，而不是把三十个图标都做成并行无缓存请求。雪碧图不是唯一办法，HTTP/2 下过多合并反而降低缓存粒度。

## 11 预检缓存和自定义头

每个业务请求都带 `X-Request-Id`，导致每个接口先有一次 OPTIONS。有哪些处理方式，各自代价是什么？

**答案**

服务端对 OPTIONS 返回 `Access-Control-Allow-Headers: X-Request-Id` 和 `Access-Control-Max-Age: 7200`。浏览器在两个小时内不再为同一 URL、方法和头集合作预检。Max-Age 有浏览器上限，Chrome 会把过长的值截短。

把请求 id 放进 POST 正文可以避免这个自定义头，但 GET 没有正文，而且日志中间件也不容易读到。不要用 `no-cors` 规避，那样业务代码读不到响应。预检按 URL 缓存，带随机 query 的地址每次仍会预检。

## 12 富文本消毒

实现一个只允许 `p`、`a`、`strong` 的渲染。`a` 只允许 `href` 和安全的 `target`。请写出必须拒绝的输入。

**答案**

用 DOMParser 解析后遍历节点，不在白名单里的元素替换成它的文本子节点，或直接删除。属性只保留允许的名字。`href` 用 `new URL(value, location.origin)` 解析，协议必须是 `http:` 或 `https:`。`target` 只允许 `_blank`，同时写入 `rel="noopener noreferrer"`。

必须拒绝：

```html
<p onclick="alert(1)">x</p>
<a href="javascript:alert(1)">x</a>
<a href="https://evil.com@trusted.com">x</a>
<strong><img src=x onerror=alert(1)></strong>
```

字符串替换 `<script>` 是不够的，大小写、换行、实体编码都能绕过。使用经过安全审计的消毒库，自己写时至少基于 DOM 而不是正则。

## 13 原型污染的修复

写一个安全的 `set(object, path, value)`，路径来自用户。说明测试用例。

**答案**

```js
const blocked = new Set(['__proto__', 'prototype', 'constructor'])
function set(object, path, value) {
  const keys = path.split('.')
  let current = object
  for (let i = 0; i < keys.length - 1; i++) {
    if (blocked.has(keys[i])) throw new Error('非法键')
    if (current[keys[i]] === null || typeof current[keys[i]] !== 'object') {
      current[keys[i]] = Object.create(null)
    }
    current = current[keys[i]]
  }
  const last = keys[keys.length - 1]
  if (blocked.has(last)) throw new Error('非法键')
  current[last] = value
}
```

测试 `__proto__.polluted`、`constructor.prototype.polluted` 都不能让 `({}).polluted` 变成真值。中间层使用 `Object.create(null)`，避免继续沿原型赋值。这只解决路径写入，不代表可以把用户对象展开进配置。

## 14 postMessage 的来源

iframe 子页面向父页面发初始化数据。写出父页面的监听，并说明只判断 `event.origin` 还漏什么。

**答案**

```js
window.addEventListener('message', event => {
  if (event.origin !== 'https://child.example') return
  if (event.source !== childFrame.contentWindow) return
  const data = parseMessage(event.data)
  if (!data) return
})
```

`origin` 防止别的站点发消息，`source` 防止同一个源下另一个 iframe 发消息。`event.data` 仍要按结构校验，不能因为来源对了就执行里面的函数或 HTML。子页面要用具体的 `targetOrigin`，不要用 `*`。回复时使用 `event.source.postMessage(response, event.origin)`。

## 15 token 放在哪里

单页应用的访问令牌可以放内存、localStorage 或 HttpOnly cookie。说出每种方案在 XSS 和 CSRF 下的结果。

**答案**

内存：刷新页面就没了，XSS 只有在脚本执行期间能读到变量，持久性差一些，但仍可以被钩住发送函数。刷新后要靠一个只用于续期的 HttpOnly cookie 换新令牌。

localStorage：刷新还在，任何 XSS 都能同步读走，并且会被所有同源标签共享。不推荐存放访问令牌。

HttpOnly cookie：JavaScript 读不到，XSS 不能直接把令牌抄走，但浏览器会自动带上，所以必须用 SameSite、CSRF token 和只允许指定来源。XSS 仍然可以带着用户的浏览器去调接口，只是拿不走令牌本身。

没有一种存放方式能在发生 XSS 后还保持应用安全。存放方式决定的是令牌会不会被复制走。

## 16 点击劫持

管理页面被别人用透明 iframe 套住。写出前端能配合的响应头和它挡不住的情况。

**答案**

服务端发送 `Content-Security-Policy: frame-ancestors 'none'`，旧浏览器再加 `X-Frame-Options: DENY`。需要被自己的域名嵌入时，`frame-ancestors` 写具体源，不要写 `*`。

前端 JS 判断 `window.top !== window.self` 不可靠，因为被嵌套的页面可能根本跑不到脚本，也可能被沙箱限制。响应头要由文档本身的响应给出，CDN 缓存的 HTML 也必须带上。

## 17 React 提交和渲染

为什么渲染函数里不能发请求、不能直接改 DOM？和提交阶段有什么关系？

**答案**

渲染函数可能被反复调用，严格模式在开发环境还会故意调用两次。它的职责是用当前状态算出下一次 UI 描述，不应该有能被观察到的副作用。请求放到 effect 或事件里，DOM 修改交给 React 的提交阶段。

并发渲染时，一份渲染结果可能被丢弃，从未提交到页面上。渲染期间发请求会造成重复请求，渲染期间改外部变量会留下被丢弃那次的脏数据。提交阶段才把最终结果挂到 DOM，`useLayoutEffect` 在这次提交后、绘制前运行。

## 18 外部 store 的撕裂

React 18 并发渲染下，组件 A 和组件 B 都在渲染中途从同一个外部 store 读值。为什么可能读到不同版本？`useSyncExternalStore` 解决了什么？

**答案**

外部 store 的更新不在 React 的渲染事务里。并发渲染如果中途让出，store 已经变了，后渲染的组件会读到新值，先渲染的组件还拿着旧值。一次屏幕更新里就出现两个版本，这叫撕裂。

`useSyncExternalStore` 要求提供 `subscribe` 和 `getSnapshot`。store 变化时通知 React，React 在这次渲染中强制用同一次快照。`getSnapshot` 必须在数据没变时返回稳定引用，否则 React 会认为一直在变，进入死循环。可变数据要在更新时换成新对象，而不是改原对象还返回它。

## 19 startTransition 的边界

把筛选输入放进 `startTransition` 后，输入框仍要立刻显示每个字符。状态该怎么拆？过渡更新会被什么打断？

**答案**

输入框的值用紧急的 `setInput`，列表过滤用 `startTransition(() => setQuery(input))`。紧急更新先提交，过滤可以延后，用户不会觉得打字被列表拖住。

过渡更新可以被新的点击、输入打断。被打断的那次渲染不提交。不能把受控输入本身放进过渡，否则字符会延迟出现。过渡里的请求如果没有 abort，旧响应仍可能在结束后写状态，需要自己的请求序号。

## 20 useEffect 的过期闭包和 useEffectEvent

效应依赖 `query`，但里面的上报函数总想读到最新的 `userId`，又不想因为 `userId` 变化重新请求。怎样组织？

**答案**

请求仍然只依赖 `query`。读取最新 `userId` 的逻辑放到 `useEffectEvent`，它在调用时使用最新 props，但不成为效应的依赖。

没有这个 API 的代码里，用 ref 保存 `userId`，效应里读 `ref.current`。不要把 `userId` 加进依赖后再在效应里判断“如果只是 userId 变了就 return”，那会让请求清理函数先跑一遍，也容易漏掉真正需要重请求的情况。ref 要在渲染期间更新，而不是再放一个效应去同步。

## 21 错误边界抓不到什么

错误边界包住了子树。写出三种它抓不到的错误，并给出对应接法。

**答案**

事件回调、异步 `then`、定时器里的错误不发生在渲染期，错误边界看不到。要在回调里 `try/catch`，或在 promise 上 `.catch`，再把错误写进状态，让下一次渲染主动抛出或显示错误 UI。

服务端渲染的错误边界行为和客户端不同，水合失败要看水合错误。错误边界也不能抓它自己渲染时抛出的错误，所以兜底 UI 要简单，不要再依赖会失败的数据。

## 22 水合不一致

服务端渲染的时间戳是 `Date.now()`，客户端水合时又调用了一次，出现警告。怎样写这个时间？

**答案**

服务端和客户端第一次渲染必须产出相同 HTML。时间放到服务端渲染的 props 里传下来，客户端不要重新生成。若必须用客户端时间，先渲染占位，挂载后再在 `useEffect` 里显示真实时间，让差异发生在水合之后。

`typeof window === 'undefined'` 分支写出不同 JSX，也会水合失败。本地存储、随机 id、地区格式化都是同样的问题。水合不是重新请求一遍数据，它是让已有 DOM 和 React 树对上。

## 23 Suspense 瀑布

组件 A suspense 等待用户，用户回来后才渲染 B，B 再等待订单。两个请求没有依赖，怎样避免瀑布？

**答案**

在渲染 A 和 B 之前同时创建两个 promise，并把 promise 作为 props 传下去。子组件读取 promise 时才 suspend，但请求已经开始。

```jsx
function Page() {
  const userPromise = fetchUser()
  const orderPromise = fetchOrders()
  return (
    <>
      <Suspense fallback="用户"><User value={userPromise} /></Suspense>
      <Suspense fallback="订单"><Orders value={orderPromise} /></Suspense>
    </>
  )
}
```

不要在子组件的 effect 里才发请求，那一定晚于渲染。promise 不能在每次渲染时新建，否则会重复请求，应放在稳定的缓存或路由 loader 里。

## 24 协调和 key 的移动

列表从 `[{id:'a'},{id:'b'}]` 变成 `[{id:'b'},{id:'a'}]`。用 id 当 key 时，React 会卸载重装，还是移动？内部 state 会怎样？

**答案**

React 认出同一个 key，移动对应的组件实例，内部 state 跟着走。这是想要的结果。用 index 当 key 时，位置 0 的实例被复用，state 还留在位置 0，数据却换成了另一项。

反向列表、拖拽排序必须使用稳定 id。没有 id 时，移动会表现为输入内容串行，这不是受控输入能单独解决的，受控数据如果也按位置存放，会一起错。

## 25 一个不会撕裂的小 store

写一个最小 store，让 React 组件订阅其中的 `count`。快照引用要稳定。

**答案**

```jsx
function createStore(initial) {
  let state = initial
  const listeners = new Set()
  return {
    get: () => state,
    set(partial) {
      state = { ...state, ...partial }
      listeners.forEach(listener => listener())
    },
    subscribe(listener) {
      listeners.add(listener)
      return () => listeners.delete(listener)
    }
  }
}

function useCount(store) {
  return useSyncExternalStore(
    store.subscribe,
    () => store.get().count
  )
}
```

`set` 必须替换 state 对象。`useCount` 返回的是数字，数字比较稳定，不会因为别的字段更新而变化时，组件可以不重渲染。如果选择器写成 `() => store.get()`，任何字段变化都会换新对象，所有订阅者都渲染。服务端渲染还要提供 `getServerSnapshot`。

## 26 类型里的状态机

请求状态不要写成 `{ loading: boolean; data?: User; error?: Error }`。设计一个联合类型，并说明它禁止了哪种不可能状态。

**答案**

```ts
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: Error }
```

旧写法可以同时出现 `loading: true` 和 `error`，渲染时只能靠人肉约定。联合类型在 `status === 'success'` 分支里一定有 `data`，在错误分支里不能读取 `data`。

更新时返回完整的下一状态，不要在旧对象上补一个字段，否则类型上看起来是成功，运行时却残留着上一次的 error。

## 27 函数类型的可变性

为什么下面的赋值在严格函数类型下会报错？如果强行放开，运行时会坏在哪？

```ts
type Handler = (value: string | number) => void
type StringHandler = (value: string) => void

const onlyString: StringHandler = value => value.toUpperCase()
const broken: Handler = onlyString
broken(1)
```

**答案**

函数参数是逆变的。`Handler` 的调用者可以传入 `string` 或 `number`。`onlyString` 只保证能处理 `string`，里面调用了 `toUpperCase`。把它当成 `Handler` 后，`broken(1)` 会在运行时因为数字没有 `toUpperCase` 而抛错。

反方向是安全的：一个真正能处理 `string | number` 的函数，可以放到只传 `string` 的位置，因为调用者不会传出它无法处理的值。返回值则是协变的，实现返回的类型不能比调用者期望的更宽。TypeScript 开启 `strictFunctionTypes` 后会拒绝示例里的赋值。

## 28 条件类型提取返回值

写一个类型，从 `typeof fetchUser` 里取出它 Promise 成功后的值，不要写成手写的 User。

**答案**

```ts
async function fetchUser() {
  return { id: '1', name: 'Ada' }
}
type User = Awaited<ReturnType<typeof fetchUser>>
```

`ReturnType` 拿到 `Promise<{ id: string; name: string }>`，`Awaited` 再解开 Promise。函数如果有重载，`ReturnType` 取最后一个签名。不要同时维护一份手写 User 和函数返回值，两份会漂移。运行时校验仍然需要，类型提取不会检查接口真的返回了这些字段。

## 29 打包和长缓存

怎样配置构建，才能让没改过的模块继续命中缓存，改过的模块文件名一定变？

**答案**

使用内容哈希，而不是构建时间或版本号。一个模块内容不变，它的哈希就不变。入口运行时清单记录每个块的最新名字。CSS 里引用的图片也要带内容哈希，否则样式没变、图片变了却不会更新。

把所有小模块合成一个巨大文件时，任何一行改动都会让整个文件缓存失效。按路由拆包，把很少变化的框架放进独立 chunk。拆得过细会增加请求和加载调度成本，HTTP/2 下也不是越小越好。以路由和稳定依赖为边界即可。

## 30 source map 和错误上报

生产代码压缩后，怎样让上报的堆栈回到 TypeScript 行列，同时不把 map 暴露给用户？

**答案**

构建生成独立的 `.map`，上传到错误平台，并带上发布版本。页面只上报压缩后的文件名、行、列和版本。平台用该版本的 map 还原。HTML 和 JS 都不写 `sourceMappingURL` 指向公开地址。

map 必须和那一次构建的产物严格对应，不能用后一次构建的 map 去解前一次的堆栈。上传失败就等于这次发布没有可调试性，发布流程里应把它当成产物的一部分，而不是事后补。

## 31 INP 的三段

一次点击的 INP 很差。怎样把它拆成输入延迟、处理时间、呈现延迟？各段对应什么代码问题？

**答案**

输入延迟是从事件发生到回调开始。前面有长任务，回调在队列里等。处理时间是监听器本身的同步执行，里面做了大计算或同步布局。呈现延迟是回调结束后到下一帧画出来，通常是大规模 DOM 更新或样式计算。

用性能面板的 Interactions 或 Event Timing 看这三段。输入延迟高就拆前面的长任务。处理时间高就把过滤、排序移出点击同步路径。呈现延迟高就减少本次更新的节点，使用虚拟列表或过渡更新。不要只看接口耗时，INP 不包含等待网络之后的那次独立绘制，除非这次点击的下一帧被脚本一直占着。

## 32 被动监听和滚动

`touchmove` 监听里只有统计，没有 `preventDefault`，页面在移动端仍感觉滚动迟钝。原因和改法是什么？

**答案**

浏览器不知道监听器会不会取消默认滚动，只能等监听器执行完再滚动。把监听标成被动后，浏览器可以立刻滚动。

```js
element.addEventListener('touchmove', track, { passive: true })
```

Chrome 对 document 上的 touch 和 wheel 默认可能按被动处理。真正要阻止滚动时，监听必须是非被动的，并且只加在需要阻止的小区域上。在被动监听里调用 `preventDefault` 会警告并且无效。

## 33 主线程让出

处理两万条数据时，既不能卡住点击，又要按顺序出结果。`setTimeout(fn, 0)` 和 `scheduler.postTask` 怎么选？

**答案**

每处理固定数量就让出一次主线程，让输入和渲染有机会插入。`setTimeout` 能让出，但它是宏任务，延迟不稳定，后台标签会更慢，也没有优先级。

`scheduler.postTask(task, { priority: 'background' })` 可以把继续处理放到后台优先级，用户输入用更高优先级插进来。不支持时再退回 `setTimeout` 或 `requestAnimationFrame`。让出的粒度按“每批不超过 50ms”来切，而不是每条数据都排队，否则调度开销超过计算本身。

## 34 Worker 里做什么不合适

把排序两万个纯对象放到 Worker。写出传输方式，并说明把包含函数的对象传进去会怎样。

**答案**

```js
const worker = new Worker('/sort.js')
const buffer = new Float64Array(numbers)
worker.postMessage({ buffer }, [buffer.buffer])
```

第二个参数是转移列表，转移后主线程不能再使用这块 `ArrayBuffer`。纯数字适合这种方式，没有结构化克隆的拷贝成本。

普通对象会被结构化克隆，函数、DOM、类实例的方法都会失败或丢失。Worker 里不能访问 `document`。计算结果传回主线程也是一次拷贝或转移，如果结果巨大，要比较这份拷贝是否比主线程直接排序更贵。

## 35 容器查询和媒体查询

组件放进 240px 的侧栏和 800px 的主区域，都在同一个宽屏里。为什么媒体查询不够，容器查询怎么写？

**答案**

媒体查询看视口，不看组件实际得到的宽度。同一视口里的侧栏和主区域无法写出两套媒体查询。

```css
.card-wrap { container-type: inline-size; }
@container (min-width: 480px) {
  .card { display: grid; grid-template-columns: 160px 1fr; }
}
```

`container-type: inline-size` 让元素成为查询容器，容器自己的样式不能依赖这个查询，否则宽度和样式互相决定。查询写在内部子元素上。

## 36 层叠和 isolation

一个第三方弹层的 z-index 是 9999，把全站菜单盖住。不改第三方源码时，怎样限制它只在自己的区域里比较？

**答案**

给第三方挂载的父元素创建新的层叠上下文，并给这个父元素较低的层级。弹层的 9999 只能在父元素内部比较。

```css
.widget {
  position: relative;
  z-index: 1;
  isolation: isolate;
}
.menu { position: relative; z-index: 2; }
```

`isolation: isolate` 专门用来生成层叠上下文，不需要额外的透明度或变换。若弹层被挂到 `document.body`，父元素的上下文限制不到它，这时要改挂载点，或让菜单也挂到 body 并使用更高的应用级层级尺度。

## 37 输入法事件

自动搜索在 `change` 时发请求。中文输入拼音时每个字母都请求了一次，并且候选字被打断。写出正确的事件组合。

**答案**

用 `compositionstart` 把 `composing` 设为 true，`compositionend` 再设回 false 并用最终值请求。`input` 事件里如果正在组词就 return。

```js
let composing = false
input.addEventListener('compositionstart', () => { composing = true })
input.addEventListener('compositionend', () => {
  composing = false
  search(input.value)
})
input.addEventListener('input', () => {
  if (!composing) search(input.value)
})
```

部分浏览器在 `compositionend` 之前还会再派发一次 `input`。可以用微任务延后读取 `composing`，避免漏掉结束时的那个值，或在 `compositionend` 里统一搜索。不要在组词期间重设 input 的 value。

## 38 安全的打开新窗口

`window.open(userUrl)` 有两处风险。怎样限制？

**答案**

第一，`userUrl` 可能是 `javascript:` 或攻击者的域名。先用 `new URL` 解析，只允许 `https:`，并且 host 在名单内。第二，新窗口可以通过 `window.opener` 访问原页面。

```js
const opened = window.open(safeUrl, '_blank', 'noopener,noreferrer')
if (opened) opened.opener = null
```

链接形式用 `rel="noopener noreferrer"`。`noopener` 同时让新窗口运行在独立进程的可能性更高，原页面不会被同步脚本拖慢。不要把用户整段 HTML 放进 `open` 的第三个参数或新文档里。

## 39 设计可取消的请求层

写一个 `createClient()`，同一把 key 的新请求会取消旧请求，旧请求的取消不能触发全局错误提示。

**答案**

```js
function createClient() {
  const pending = new Map()
  return async function request(key, url, options = {}) {
    pending.get(key)?.abort()
    const controller = new AbortController()
    pending.set(key, controller)
    try {
      const response = await fetch(url, { ...options, signal: controller.signal })
      if (!response.ok) throw new Error(String(response.status))
      return await response.json()
    } catch (error) {
      if (error.name === 'AbortError') return undefined
      throw error
    } finally {
      if (pending.get(key) === controller) pending.delete(key)
    }
  }
}
```

`finally` 里要确认 Map 里仍是自己的 controller，不能把后一次请求的 controller 删掉。调用方看到 `undefined` 就知道是取消，不弹错误。真正的网络错误继续抛出。不同资源要用不同 key，否则列表请求会取消掉无关的详情请求。

## 40 组件边界

一个 500 行的页面组件同时发请求、转换数据、订阅滚动、渲染三块 UI。给出拆分方式，并说明哪一层不能依赖 React。

**答案**

数据获取放在页面或路由 loader，得到原始响应。纯函数模块把响应转换成视图模型，例如排序、单位换算和空值处理，这个模块不 import React、DOM 和图表库，便于单测。

三块 UI 各自是组件，只接收已经转换好的 props 和回调。滚动订阅放在需要它的那一个组件的 effect 里，不要让图表组件因为滚动位置变化而拿到全部页面状态。页面组件剩下组合和状态提升，目标是每块都能说出自己的输入，而不是闭包读取同一份巨大状态。
